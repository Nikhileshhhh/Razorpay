How this workspace tells the story

READING ORDER

Header (exposure, three separate state concepts, current safe action) → expected-versus-observed money path with the first divergence → investigation → evidence, candidates, notes. The rail runs the control loop in registration order and ends in commands.

NINE ARTIFACT CLASSES

Each class keeps its own label, glyph, border style and tint everywhere it appears — source fact (solid slate square), derived control (blue diamond), offline investigation (dashed violet circle), policy (teal triangle), approval (green circle-check), simulated action (dashed amber square), verification evidence (blue rule), reconciliation (paired bars), audit (inverted).

NOTHING IS PROMOTED

Candidate edges live in their own review panel and never touch the verified lane. Acknowledgement, recipient settlement and ERP requests are labelled as themselves. Only independent bank evidence plus unique allocation plus observed closure produces VERIFIED.

SIX PANELS, ISOLATED

Case detail, money path, evidence, notes, control loop and verification are six parallel validated reads. A failure scopes to its own panel with a safe Retry — see 1f — and never erases the last known financial context.

WORKSPACE ANNOTATIONS
Three separate concepts in the header

Materiality (Material · P1), lifecycle (APPROVAL REQUIRED) and financial outcome (DIVERGED) each get their own badge, glyph and tint. Evidence coverage and contradictions are two more separate badges. Exposure is the largest number on the page at 26px mono.

The path is a reading, not a graph

Two lanes, left to right, no drag, no zoom, no editing. The expected lane is always fully visible; the observed lane renders only persisted nodes and stops at the divergence marker. The Linear view toggle and the always-present ordered text alternative carry every node and edge attribute, so nothing depends on visual position. Screen readers get the linear order by default.

Edge classes never merge

Verified and derived edges are solid 2px blue. Expected-only edges are 1px dashed grey. Candidate, rejected and contradicted edges are dotted violet and live only in the candidate review panel (1f) — they are never drawn between lane nodes, at any confidence.

Investigation is offline and bounded

Exactly four numbered sections, a metadata strip of nine forensic fields, a Low/Medium/High confidence band paired with coverage and blockers, and an explicit "Not safe to act". No chain-of-thought, no typewriter effect, no fabricated stages, no persona. A genuine queued or running read shows only the backend stage name and timestamps.

Evidence rows are two-tier

Primary line: source, canonical and raw type, event time, amount, authority class. Second line, same row scope: ingested time (separately labelled), currency, signature status, duplicate status, quarantine status and the evidence reference. Payloads stay collapsed and redacted — safe references only, never signatures, secrets or bank/card data.

Rail order is the control loop

Plan → policy → approval → simulated action → verification → reconciliation, then commands. The two cards that decide what happens next (policy, approval) are expanded; the rest collapse to one trustworthy line with an "Expand immutable references" disclosure for IDs, versions and hashes.

Mutation discipline

Effect-oriented labels only. Dialogs show the exact plan, version or hash. No optimistic success: request-in-flight → refetch authoritative state → announce. OUTCOME_UNKNOWN offers only Check status (never Retry, never a new idempotency key). APPROVAL_STALE / VERSION_CONFLICT closes the decision UI and forces re-review.

MONEY FORMATTING — BINDING ANNOTATION

Every monetary API value is a decimal string in minor units, formatted with BigInt only — never Number(), parseFloat() or floating-point arithmetic, and never summed, netted or compared in the browser.

amount_minor: "45500000"
// render BigInt → ₹4,55,000.00 INR
// forbidden Number(amount_minor)/100

Plan parameters carry the same string verbatim into dialogs and audit. Screen readers get spoken money ("4 lakh 55 thousand rupees") alongside the printed value.

Six parallel validated reads

/v1/cases/:id, /money-path, /evidence, /notes, /control-loop, /verification — each schema-validated, each independently retryable, none blocking the others. No panel derives a value another panel owns.

Keyboard & announcements

Full operation for the lanes/linear toggle, every disclosure, candidate review, notes, dialogs, commands and audit links. Dialogs and drawers trap focus, close on Escape and restore focus to their trigger. Mutation completion, poll completion and version conflicts announce politely; validation errors surface in an error summary linked to the invalid field.

Structure & motion

One h1 (the Case ID), then ordered h2s: money path, investigation, evidence, candidates, notes, control loop. main, aside and status landmarks; semantic tables and lists throughout; timestamps carry exact detail with accessible UTC. Under reduced motion, disclosures and lane updates are instant state changes — no movement carries meaning.

Deliberately absent

No chat or assistant, no Settings, no standalone Controls / Reconciliation / Money Paths navigation, no editable graph, no chain-of-thought or typewriter output, no optimistic financial success, no generic "Confirm", and no client-computed totals or verdicts anywhere.
