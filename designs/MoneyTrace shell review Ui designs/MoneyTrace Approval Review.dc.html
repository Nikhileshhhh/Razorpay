What this screen has to make impossible

CONFUSING SYNTHETIC WITH REAL

"Synthetic action — no real money movement" appears in the page notice, at the top of the drawer, on the SIMULATED ACTION artifact card, and inside the final confirmation dialog. The primary button never reads "Approve" alone — it always reads "Approve simulated remediation".

DECIDING WITHOUT THE BASIS

Six decision-basis groups sit above the action area, none truncated, no hash hidden behind hover. The confirmation dialog restates action, target, maximum impact, both versions, evidence hash, basis hash and expiry — so the last screen before a decision is itself a full basis.

ONE-CLICK MOMENTUM

Queue never offers "Approve" — only "Review approval". Every decision needs a second deliberate dialog; reject and request-more-evidence require a bounded reason. No optimistic success: in-flight → authoritative response → refetch → announce.

CLIENT-SIDE AUTHORITY

Reads come from GET /v1/approvals; decisions go to the case-scoped approve, reject and request-more-evidence mutations. Hidden controls are ergonomics, not security — the server remains authoritative and separation of duties is enforced there.

QUEUE & DRAWER ANNOTATIONS
The queue cannot decide

Every actionable row offers only "Review approval"; historical rows offer "View basis". There is no inline Approve, no bulk selection, and no keyboard shortcut that decides. Ten columns fit 1,114px with border-box cells.

Expiry, three ways

Local time, relative urgency in words, and exact UTC in the accessible name. Urgency escalates by glyph and border as well as tint: neutral > 24h, amber clock inside 24h, red triangle inside 1h, dashed neutral once expired. Never colour-only, never relative-only.

600px drawer, queue preserved

Within the 520–640px band. The queue stays rendered behind a scrim so the reviewer keeps their place; the reviewed row keeps a blue rule and tint. role="dialog" aria-modal, focus trapped, Escape closes, focus returns to the row's Review link. The action area is pinned after all six groups — the basis column scrolls, groups never shrink, and no field is truncated.

ImmutableHashField

Short form + copy button + Reveal disclosure. The accessible name carries the full value, so a screen-reader user never depends on the truncation or on hover. Rendered as read-only text, never an input; the idempotency key uses the same treatment and is explicitly "never regenerated".

Endpoints represented

GET /v1/approvals for queue and detail; case-scoped approve, reject and request-more-evidence mutations for decisions. The design never constructs a substitute approval state locally — no optimistic row edits, no locally derived state or counts.

Client visibility is not security

Hiding or disabling decision controls is ergonomics only. Role, separation of duties, basis freshness and expiry are all enforced server-side, and a denial is surfaced with its reason rather than silently swallowed — see 1d.

MONEY FORMATTING — BINDING ANNOTATION

Amount-impact strings arrive as decimal strings in minor units and are formatted with BigInt only — never Number(), parseFloat() or any client-side financial arithmetic. No summing across approvals, no queue totals, no thresholds computed in the browser.

amount_minor: "45500000"
// render BigInt → ₹4,55,000.00 INR
// forbidden Number(amount_minor)/100

The same string is carried verbatim into the plan parameters, the confirmation dialog and the audit record. Screen readers hear the full spoken amount alongside the printed value.

Server authorization is authoritative

Role, separation of duties, basis freshness and expiry are enforced by the case-scoped mutations. Client-side hiding or disabling is convenience; a denial always surfaces with its reason and is written to Audit. The design never constructs a substitute approval state locally.

Accessibility contract

Semantic tabs with aria-selected; real table headers with scope and a visually-hidden caption; one h1 and ordered group headings; every dialog labelled and described, focus-trapped, Escape-closable, focus restored to its trigger. Reason validation surfaces an error summary linked to the field. Approval changes announce through a polite live region. Status is never colour-only, time never relative-only, and full monetary values are always available to screen readers.

Density rhythm

4px base. Queue rows 44px with 9/7 cell padding; drawer 18px gutters, groups 9/11 with 5px row gaps and a 150px label column; decision buttons 36px in the drawer, 34px in dialogs. Type 10.5–11.5px for basis values, 14px for the maximum impact inside groups, 20px for the drawer's headline amount.

Deliberately absent

No generic Confirm, no inline queue Approve, no bulk approve, no full-text search, no dismissable policy warning, no optimistic state, no editable hash field, no override on expired or invalidated records, and no chat, Settings, Controls, Reconciliation or Money Paths navigation.
