Queue design decisions

TWO SEPARATE TRUTHS

Lifecycle state (where the case is in the process) and financial outcome (what happened to the money) are two columns with two different visual languages — pill badge versus uppercase mono verdict. They are never merged into one "status".

TWELVE COLUMNS, HONESTLY

All twelve required columns fit the 1,126px region at 1,114px — border-box cells, 6px padding, abbreviated headers whose full wording lives in the accessible name. Case ID and Exposure are pinned so narrower viewports scroll horizontally instead of dropping columns.

NO IMPLIED AUTHORITY

No checkboxes, no bulk actions, no "Create case", no export. The chevron is navigation only. Next safe action is printed as plain language, not a button, so the queue never looks like it decided anything.

ALL CONTENT SYNTHETIC

Rows represent the four demo stories over persisted synthetic responses. Filters, sort, cursor and supported search all live in the URL; every visible value is validated API data with backend-allowlisted query values.

QUEUE ANNOTATIONS
Lifecycle ≠ financial outcome

Lifecycle is a tinted pill with a shape glyph (Open, Investigating, Approval required, Verification pending, Reconciled, Abstained). Financial outcome is uppercase mono with its own glyph (DIVERGED, ACTION PENDING, VERIFIED, REVERSED, UNRESOLVED). A Reconciled case can be REVERSED; a Reconciled case can be VERIFIED — the two columns must be read together.

All twelve columns fit — no scroll at 1440

The table lands at 1,114px inside the 1,126px region: border-box cells, 6px cell padding, abbreviated header labels (DIVERGENCE / CTL, CTRA., OPENED) whose full wording lives in each header's accessible name. Case ID and Exposure stay pinned so that below ~1,240px the region scrolls horizontally — announced in the toolbar strip, focusable with tabindex="0" and an accessible name — and the money column never detaches from its identifier.

Row states without colour alone

Hover = 2% tint. Current row = 3px left blue rule plus tint (row 1 shown). Focus = 2px blue ring on the Case ID link, not the row. Zebra banding aids scanning across twelve columns. Row click is a convenience only; Case ID and the trailing chevron are the real navigation, both with accessible names.

URL is the source of queue state

Lifecycle, control, evidence, owner, policy, min/max exposure, sort, cursor and supported search all serialise into the query string (shown under the sort control), so the queue is shareable and back/forward safe. Opening a case carries the same query state so the case page can return exactly here.

Contradictions never vanish

Zero renders as a hollow-circle glyph plus "0" in neutral grey — never blank, never a dash. Non-zero uses the warning triangle: amber for one, red at two or more, always with the count in text.

Keyboard order

Search → each filter control → sort → filter chips (each removable) → Clear filters → table scroll region → sortable header buttons → Case ID links and chevrons row by row → Previous / Next. Result changes announce politely: "Showing 1–8 of 21 current results".

Deliberately absent

No "Create case" (cases come from persisted control facts), no checkboxes or bulk remediation, no export, no saved views, no column builder, no client-side full-dataset search, and no chat, Controls, Money Paths, Reconciliation or Settings navigation.

Truthful result text

With a total: "Showing 1–8 of 21 current results". Without one: "8 results on this page". Never invented page numbers, never a total the cursor API did not return. Changes announce through role="status" aria-live="polite".

Semantic table contract

Real table markup, visually-hidden caption, scope="col" on every header, sort state on the header button (arrow glyph + aria-sort, never colour alone), and money cells carrying a spoken label ("4 lakh 55 thousand rupees exposure").

MONEY FORMATTING — BINDING ANNOTATION

Every monetary API value is a decimal string in minor units and must be formatted with BigInt only. Never Number(), parseFloat() or floating-point arithmetic — not for display, not for sorting keys, not for filter bounds.

exposure_minor: "45500000"
// render BigInt → ₹4,55,000.00 INR
// forbidden Number(exposure_minor)/100

Min/max exposure filters send minor-unit strings too. Sorting is server-side; the browser never compares money numerically.

All visible state is validated API data

Lifecycle, financial outcome, evidence coverage, contradiction count, policy status, owner and next safe action are read-model fields. Every filter and sort value is chosen from a backend allowlist and rejected server-side if tampered with in the URL. The queue computes nothing — no client-side totals, thresholds, ranking, or derived verdicts.

Focus & target sizes

One focus treatment: 2px #1a63d8 at 2px offset, visible on white, tinted and zebra rows alike. Toolbar controls are 32px tall with 44px pointer targets via padding; the chevron target is 22px inside a 40px cell. Header sort buttons are focusable and expose aria-sort.

Density rhythm

4px base. Row height 40px, cell padding 9/10, header 8/10, toolbar rows 32px with 9px gaps, 12px between page blocks, 20px page gutters. Type: 11–11.5px in cells, 13px exposure, 24px h1 — dense but never below the enterprise floor.
