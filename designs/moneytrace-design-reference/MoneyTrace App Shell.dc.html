1MoneyTrace — shared application shell, responsive frames & component specs

Assumptions & design reasoning

POSITION

Case-first control plane, not an assistant. The shell's job is to make provenance, environment and identity legible before any number is read. No chat launcher, notification centre, settings menu or real-money badge exists in this system.

VISUAL LANGUAGE

Public enterprise-dashboard conventions only: neutral cool canvas, white surfaces, 1px restrained borders, one blue primary, semantic status pairs. Original MoneyTrace wordmark and trace motif — no third-party logo, illustration or private token value is reproduced.

OPEN ASSUMPTIONS

(1) Header metadata order holds at ≥1360px and folds to a secondary row below it. (2) Approval badge is rendered only from a capability count. (3) Page body here is deliberately placeholder — KPIs belong to page-level specs, not the shell.

MOBILE RULES

The top bar always carries four things: navigation trigger, MoneyTrace wordmark, the environment badge, and the role trigger. Nothing about identity or environment is truncated or hidden — the badge shortens to "Synthetic" only with the flask glyph retained, and its accessible name stays "Synthetic Demo environment".

Dataset time stays visible in a 40px strip that doubles as the sheet trigger; manifest hash, refresh and Demo scenarios move into the structured sheet rather than an overflow menu, so each row can carry its own label, value and secondary explanation.

Degraded and reset banners are never suppressed at small sizes; they wrap to multiple lines and keep the "View Data Health" action as a full tap target. All touch targets are ≥44px.

MobileNavigationDrawer — role="dialog" aria-modal="true", focus moved to the close button on open, focus trapped, Escape and scrim tap close, focus restored to the trigger, background inert. Slide-in is a 160ms transform; under prefers-reduced-motion the drawer simply appears.
1fArtifact classes & status language — shared vocabulary the shell must keep distinct
NINE ARTIFACT CLASSES · LABEL + GLYPH + BORDER + TINT + HEADING TREATMENT ARE ALL DISTINCT
SOURCE FACT
Ingested field, unmodified

Solid slate square, filled glyph. Never re-labelled as evidence or conclusion.

DERIVED CONTROL
Computed from source facts

Diamond glyph, blue tint. Always shows the inputs it was derived from.

OFFLINE DEMO INVESTIGATION
Analysis on synthetic data

Dashed border marks non-production reasoning. Candidates are candidates, never verified links.

POLICY DECISION
Deterministic rule outcome

Triangle glyph, teal. Cites policy id and version; no probabilistic language.

HUMAN APPROVAL
Named person, timestamped

Filled circle-check. Records the demo identity that decided, not "the system".

SIMULATED ACTION
No money moved

Dashed amber square. Reads "Action acknowledged—not yet verified", never "Success".

VERIFICATION EVIDENCE
Independent bank record

White surface with a hard blue rule. Downstream acknowledgement and recipient settlement never qualify.

RECONCILIATION
Two ledgers compared

Paired-bar glyph. States both sides and the residual, including "No exposure".

AUDIT
Append-only record

Inverted surface — visually unmistakable. Includes denied attempts and role changes.

MONEY FORMATTING — BINDING DESIGN ANNOTATION

API money arrives as a decimal string in minor units. All display formatting must go through BigInt. Never Number(), parseFloat(), or floating-point arithmetic — including intermediate sums, sorting keys, and chart values.

amount_minor: "1250075"
// render BigInt(amount_minor) → ₹12,500.75
// forbidden Number(amount_minor)/100

Amounts render in monospace with tabular figures, right-aligned in tables, currency code stated once per column header. Negative values use a leading minus and never colour alone.

SHELL RULES
Spacing rhythm

4px base. Control padding 8/10, chip gaps 6/8, header gutter 24, main gutter 40 (24 tablet, 12 mobile), 36px above the h1, 24px between h1 block and first content, 16px inside cards. Nav item height 34 desktop, 44 rail, 48 drawer.

Surface hierarchy

Canvas #f6f7f9 → chrome and cards #ffffff → secondary strips #fafbfc → overlays #ffffff with a single 24px shadow. Elevation is used only for things that float (menu, drawer, sheet); everything else separates with 1px borders. Two background colours in the whole shell.

Status treatment

Every status is glyph + text + tint. Amber is "safe warning", red is reserved for actual failure or blocked closure, dashed neutral means absent data, violet means environment. Colour alone never carries meaning, and no status string is vague.

All visible state is API-derived

Nothing in this shell is inferred from build config, hostname or branding: badge counts, source status, manifest hash, evaluation time and available demo actions all come from capability and dataset responses. When a field is missing the UI says "No data" or "Source unavailable" — it never falls back to an optimistic default, and it never renders "Live".

Out of scope by rule

No chat launcher or assistant, no notification centre, no settings menu, no marketing illustration, no real-money badge, no KPIs in the shell, and no navigation item beyond the five above — including Controls, Reconciliation and Money Paths, which are surfaced inside cases, not in navigation.
